# 人工流星による FF 検出の見逃し率の測定（次のセッションの開始メモ）

2026-11-21 作成。次のセッションで、そのまま着手できるようにまとめた。背景は `docs/ff-detection-improvement-20261120.md`（特に §9）。

## 1. 目的
- FF 検出が**見逃した流星**を数える。いまの確認は「検出したものが本物か」（適合率。11/21 の夜で約92%）だけで、**再現率（見逃し率）が分かっていない**。
- 本物の流星は、見逃したものを人が探すしかない。そこで、**既知の人工流星を、保存済みの実ブロックに足して**、明るさ・長さ・速さごとの検出率を測る。
- 得られるもの:
  1. 明るさ別の検出率の曲線（暗い夜 / 静かな夜 / BCSH オン・オフ）
  2. 閾値（σ=5、段 40/20/12、段階の下限）を変えたときの、見逃しと誤検出の釣り合い
  3. BCSH オンでノイズが半分になった分、閾値をどこまで下げられるか

## 2. 方法
実ブロックの4面（maxpixel, maxframe, avepixel, stdpixel）に、人工の線を書き込んで、`ff_detect_meteor_with` を当てる。**ノイズは実物をそのまま使う**ので、暗い夜の高ゲインのノイズも再現できる。

### 人工流星の作り方（1本ずつ、ブロックのコピーに書き込む）
1. パラメーターを決める: 始点 `(x0,y0)`、向き θ、長さ L（px）、速さ v（px/フレーム）、開始フレーム f0、ピーク `A`（avepixel に対する超過、ADU）。
2. 継続フレーム数 `n = L / v`（1 以上）。フレーム k（0..n）の位置は線上の `k·v` の点。
3. 各フレームで、位置を中心に、σ≈1 px の点広がり（PSF）で、超過 `A` の点を描く。
4. **maxpixel 面**: 各画素で `max(実の maxpixel, avepixel + 描いた値)`。
5. **maxframe 面**: 描いた値が実の maxpixel を上回った画素だけ、そのフレーム番号（`f0 + k`、0..255）に書き換える（上回らなければ変えない）。ここを忘れると、時間相関（`min_corr`）が壊れて、検出されない。
6. **avepixel 面**: 画素ごとに `+ 描いた値 / 256`（影響は小さいが、足しておく）。
7. **stdpixel 面**: 変えない（uint8 に量子化されていて、影響は 1 未満）。
8. 線が、検出マスク（`mask.bin`、80×45）の無効セルや、画像の端 8 px 以内に入らないように、始点を選ぶ。

### 掃引する範囲（最初の案）
| 項目 | 値 |
|---|---|
| ピーク A（ADU） | 6, 8, 10, 14, 20, 30, 50, 100 |
| 長さ L（px） | 15, 30, 60, 120 |
| 速さ v（px/フレーム） | 2, 5, 10, 20 |
| 向き θ | 一様乱数 |
| 位置 | 一様乱数（マスク有効、端から 8 px 以上） |
| 1 セルあたりの試行数 | 各ブロックに1本ずつ、100〜200ブロック |

- ブロックに**流星を1本だけ**足す。もとのブロックに実の検出があれば、人工の線との一致（端点が 15 px 以内。`ff_redetect.rs` の `--truth` と同じ基準）で、人工のものだけを数える。
- ベースライン（人工流星なしでの検出）も同時に走らせて、誤検出を数える。
- A の目安: 11/21 の夜で、一致した星のピーク（avepixel に対する超過）は、中央値 19、明るい星で 61。

## 3. 実装の方針
- 新しい例 `crates/solver/examples/ff_inject.rs` を作る。`ff_redetect.rs` と同じく、`#[path = "../../atometd/src/ff_detect.rs"]` で検出器を取り込み、FITS の読み込み（`read_fits`）も流用する（コピーするか、共通化する）。
- 入力: マスク、FITS のディレクトリ、掃引の設定、`--variant`（`ff_redetect` と同じ書式の閾値の変種）、乱数の種。
- 出力: セルごと（A、L、v）× 変種ごとの検出率（段階 A / A+B / A+B+C）、ベースラインの誤検出数。CSV と、検出率の曲線（matplotlib）。
- 人工の線の描画は、`ff_detect.rs` のテストにある合成の関数（`b.maxframe[i] = (f0 + (f1 - f0) * t).round() as u8;` 付近、600行前後）が参考になる。
- 先に、**1ブロック・1本・明るい線（A=100）で、検出されることを確認する**（描画の誤りを、ここで見つける）。
- 検出器の FfBlock は、`maxframe: Vec<u8>`（0〜255）。fps が 25 のとき、256 フレーム = 10.24 秒。

## 4. 実験の順番
1. 明るい線（A=100）で、描画の確認。
2. 現在の既定（新条件）で、掃引し、検出率の曲線を取る。夜は3つ（11/19〜20、11/20〜21、11/14）。
3. 変種で比べる: 旧条件、`sigma_k` を 5→4→3、`levels` を `40/20/12`→`40/20/10/8`、`A.min_speed` などを動かす。各変種で、見逃しと、ベースラインの誤検出（人工流星なしの段階A/B/C の件数）を並べる。
4. BCSH オンの夜で、閾値を下げて、誤検出が増えないかを確認し、増えない範囲で、検出率が上がる設定を探す。
5. 実の流星（`labels.txt`、`truth17.txt`、11/14 の19件）が、変更後も、落ちないことを確認する。
6. 結果を `docs/` に書く。結果が良ければ、`ff_detect.rs` の既定値を変える（ただし、実機での検出時間 15 秒のウォッチドッグを確認する。段を増やすと遅くなる）。

## 5. 注意点
- 人工流星は、点広がり（PSF）、尾の長さ、明るさの時間変化（実際の流星は、明るさが途中で変わる）が、単純化されている。検出率の**絶対値は、目安**として扱い、**変種どうしの比較**に使う。
- 実の流星は、虫・飛行機とも似ていて、単局では区別できない。虫も、検出すべきものとして数える（本ドキュメント群の基準）。
- ブロックの時間配置（流星が、ブロックの端をまたぐ）は、扱わない。
- 閾値を変えるときは、**暗い夜と静かな夜の両方**で確認する（片方に合わせすぎない）。
- `ff_redetect` 系のツールは、テスト用ビルドと、例のビルドが別。`cargo build --release -p solver --example ff_redetect` で、例を作り直す（`cargo test` では更新されない）。
