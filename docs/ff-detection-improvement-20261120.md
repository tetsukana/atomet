# 2026-11-20 FF検出の見直し：暗い夜の見逃しと誤検出（検証結果と変更点）

2026-11-19 20:00〜11-20 の夜に、FF検出（256フレーム）とリアルタイム検出の誤検出が急増した。原因を調べ、検出条件を見直した。
**結論（主観を含む）: 検出精度は劇的に良くなった。** ただし、確認は**保存済みブロックでの再検出（PC上）**までで、**実機のファームでは未確認**（§7）。

- 時刻はすべて JST（FITS名・サイドコー）。デバイスログは UTC。
- 方法の土台: `docs/ff-detection-validation-method.md`、研究計画: `docs/ff-detection-research.md`、前回の夜: `docs/night-report-20261118.md`。

## 1. 何が起きたか
- 11/19 20:00 以降、段階Cが1時間に150〜850件、実時間検出も1時間に最大1,700件（ほぼ全ブロックで検出）に増えた（前日は段階Cが約10件/時、実時間検出は数件/時）。
- 同時に、**明るい流星の見逃し**があった。例: 20261120_021656 は実時間検出では10フレームの明瞭な追跡が出ていたのに、FF検出はゼロ。

## 2. 原因
- **ゲインとノイズ**（ユーザーの観察）: AE は画面全体の明るさでゲインを決める。建物の明かりが映ると全体のゲインが下がりノイズが減り、画面全体が暗いとゲインが上がってノイズが増える。暗い夜は高ゲインで、閾値を超える画素の割合が約1%（前々夜）から約12%（今夜02〜04時台）に増えた。星の見える暗い空が観測の本来の条件なので、**暗くて高ゲインの環境で正しく検出できなければならない**。
- **見逃しの機構**: ノイズの粒が線と連結し、1つの塊になって直線として判定されない。閾値の段が15/12だけだったため。段に40/20を足すと、ノイズが消えて明るい流星が孤立する。
- **誤検出の機構**: 段階Cの下限（画素数8、速さ0.4）が緩く、ノイズの粒が通る。実時間検出は、確定した追跡が追跡のつなぎ上限（40 px/フレーム）に張り付き（中央値36）、画面の左端に沿う追跡と、下限すれすれ（中央値19 px）の短い線が大量に出ていた。
- ISP のノイズ除去（YDNS）は 11/19 11:53 に切れたが、昼間のノイズは変化前後で同じで、**因果は未確定**（→ 後の追記 §9 で、BCSH オフが主因の可能性が高いと分かった）。

## 3. 評価の基準（重要）
- **虫は単局では流星と原理的に分離できない**（薄明に多く、形も似る）。したがって、**くっきりした流星状の線は、虫も含めて正解（検出すべきもの）に数える**。誤検出に数えるのは、ノイズの断片、飛行機の点線（点滅灯）、建物・雲の縁、画像の端のノイズ。
- 正解は、**11/19〜20の夜の32件**（確定は 02:16:55 など。残りは助手が目視で選んだものをユーザーが採用）。静かな夜の比較用に、**11/14 の本物19件**（`review.csv`）。
- 最初は、ユーザーが「段階Aの57件のうち流星は3件だけ」と判定した。その後、段階A以外にも見逃しが多数あることが分かり、正解を32件に拡張した。

## 6. 試して採用しなかった案

- 継続フレーム数だけの条件: 本物7件を失う。ノイズの特徴は「長く続いて遅い」で、速さの下限で足りる。

## 9. 追記（2026-11-21）: BCSH が主因、11/21 の夜の結果
### BCSH（CLM/BCSH、ISP バイパスのビット12）
- **同じゲイン（42.3 dB）・同じ露出で、BCSH オン／オフを31秒違いのブロックで比較**（空の領域）: 時間方向のノイズ（stdpixel の中央値）が **オン1 → オフ2**、max−ave が12を超える画素が **0.0% → 2.7%**。星のピーク（一致した437個の中央値）は 19 と 18 で**変わらない**。空間方向のノイズも同じ。平均画像はオンのほうが約11明るい。→ **オンで、星の信号を保ったまま、時間方向のノイズだけが半分**。
- **夜どうしの比較**（空の領域、閾値12を超える画素の割合）: 11/19〜20 の夜（オフ）は 00〜01時 11.9%、02〜03時 11.7%、04〜05時 17.6%。11/20〜21 の夜（オン、ゲインは同じかやや高い45〜46 dB）は、どの時間帯も **0.01%**。
- **BCSH オンになった時刻**: 11/20 21:53 以降（21:50〜21:52 に比較用の短いオフ区間）。夜のあいだ、ずっとオン。
- **出荷時の状態はオン**: 起動スクリプト（`overlay_rootfs/etc/init.d/S90atomet:50`）が、起動のたびに `/atom/etc/sensor/gc2053-t31.bin`（カメラ内蔵）を `/media/mmc/gc2053-t31.bin` にコピーして上書きする。この SD 上のファイルの `TOP_BYPASS` はビット12が0（オン）。`isp_bypass` が空なら（コードの既定）、atometd はバイパスを設定しないので、オンのまま。
- **11/19〜20 の夜にオフだった理由**: `atomet.toml` の `isp_bypass`（WebUI の設定。32個）が、出荷時の設定を上書きしていた。11/19 11:53 の YDNS オフと同時に、BCSH も切れた可能性が高い（その時刻の設定は残っておらず、未確認）。**今回の誤検出の洪水は、BCSH（と YDNS）を切ったことが主因だった可能性が高い。**
- 注意: `E:\source\tiziano-params\gc2053.bin`（3/17）は、実験用に作ったファイルで、出荷時のものではない（`TOP_BYPASS` が、ビット8以外すべてバイパス）。出荷時の状態の根拠には使えない。
- `D:\gc2053-t31.bin` と 3/17 の `gc2053.bin` を `tiziano-params decode` で比べると、違うのは `TOP_BYPASS` だけ（1,095個中）。

### 残った課題
- 人工流星による見逃し率の測定 → `docs/ff-artificial-meteor-plan.md`。

- 放射点の偶然の一致の見込み（`tools/ff-analysis/sky/ff_showers.py` の確率計算）を、11/21 に当てる。
- 虫の点線と下端の点の列を、放射点の判定から除く扱い（虫は検出としては正解）。
